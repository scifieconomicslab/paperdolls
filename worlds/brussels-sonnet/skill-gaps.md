Format: **#N — skill §section** — what happened — suggested fix.

1. **skill.md routing table, Preflight row** — says load `paperdolls-technology` §Preflight; that skill has no Preflight section (it says "Load at preflight" but only holds pins/build rules). The real preflight commands are in `paperdolls-pipeline` §Preflight. Fix: point the row at pipeline §Preflight (or add the section to technology).
2. **paperdolls-pipeline §Preflight / tools/check-env.py** — "Every line must PASS" but on this checkout 5 lines FAIL: NetLogo 7.0.4 absent (expected), and `reference/render/catalogue/data/families.json`, `tools/page`, `tools/page/src/generated/catalogue.ts`, `tools/check-schemas.py` are missing ("run from the repository root" remedy is wrong: I was at the root; the files do not exist). The minimal repo does not contain the page project that technology §6 / scene-craft assume. Fix: either ship tools/page + catalogue, or make check-env.py only require what the minimal repo has and say where the page project comes from.
3. **skill.md / pipeline** — Never says where the per-world page project (`PAPERDOLLS_WORLD=… npm run build` "from the world's page project") comes from. Only `worlds/conformance/page` exists, which the task forbids modifying. Fix: document "copy worlds/conformance/page to worlds/<name>/page" or provide a template under reference/templates/.
4. **skill.md Opening / Gate 1** — "Then ask for the model" but the model path is already supplied by the launching context; skill has no instruction for a pre-supplied model. Minor.
5. **paperdolls-pipeline §Gate 2 vs. Preflight** — The user named the world (`brussels-sonnet`) in reply to a preflight question, before Gate 1. The pipeline has no rule for a name arriving early; I created the tree (`mkdir`) early to hold this file but have not yet done Gate 2 (description, world record). Fix: say a name given early is recorded and re-confirmed at Gate 2.
6. **paperdolls-netlogo-to-ts §1 / pipeline Failure playbook ("Non-spatial model — stop")** — great-retrofit-v3 has households living in buildings, but buildings have NO coordinates: they are a synthetic table (lognormal footprints, random storeys/tenure, `scene-seed`) drawn as one patch per building in a 25-wide grid. Nothing in the file mentions Jette or Brussels (the place comes only from the user's task). The skills only distinguish "spatial" vs "non-spatial"; they don't cover "anchored to structures but with a synthetic, not real, building table". The binding (agents→structures) must therefore invent a mapping of 200 synthetic buildings onto real OSM buildings. Fix: add a section for "model owns a building table with no geometry": map by count/size-rank/tenure, label as assumed, and say what the Gate 3/4/5 report must disclose.
7. **paperdolls-netlogo-to-ts §1** — model's plots/monitors are mostly computed in `compute-series-metrics` with strings (quintile vectors as formatted text); extracting "declared outputs" means reading reporters rather than pen names. Skill says "plot pens, monitors, series" but gives no guidance on vector-valued (per-quintile) series. Fix: say how to split a list-valued monitor into named series.
8. **paperdolls-pipeline §Gate 1** — No guidance for user changes that exceed the model's declared ranges. User asked: horizon default 360 (=slider max, so "double" leaves no headroom) and `n-buildings` = real residential count from the map (slider max 400, patch grid holds 400). This diverges the TS model from the NetLogo model; parity (Gate 6) can only run at n-buildings ≤ 400 and the Gate 6 text does not say how to handle "TS model scaled beyond the NetLogo model". Also: the NetLogo model's O(n²) list code probably cannot run thousands of buildings. Fix: add a "scaled-beyond-source" rule to netlogo-to-ts §4/§5 (parity at source-range, scaling test separately).
9. **skill.md routing, Gate 2b row** — The Gate 2b step (pipeline) says "ask the world family and palette/genre" but no skill says how to present the 12 `real` regions (nw, uk, ws…) to the user or which one fits a given city. Had to open `palettes.json` and infer Brussels → `nw`. Fix: a one-line region→countries table in families.md `real`.
10. **paperdolls-art-direction §2 (palette table) / palette-method §1** — accent band says C 0.10–0.16 but at L 0.58–0.64 and hues 205–235° that chroma is out of the sRGB gamut (0.13 at h235 clips); had to drop to C 0.100–0.105. Fix: note that accent C max depends on hue (blue/teal ≈ 0.10) or give a per-hue ceiling.
11. **paperdolls-art-direction §1** — says to ask the "moment" question when the description is thin; the user answered "a nice sunny day". No guidance on turning a very short answer into a specific moment (hour, month, key elevation). I chose 3 pm late May and flagged it as my invention. Fix: a table of moment → key azimuth/elevation/K; the palette-method "ground ≥ 0.94 when key elevation < 35°" rule is the only link now.
12. **paperdolls-art-direction §2 (palette) vs. data ramp** — the only worked sequential ramp offered for warm brick worlds is the exemplar's "heather"; a second brick world gets the identical ramp unless the author invents another. Fix: offer 2–3 vetted alternatives for warm worlds.
13. **art-bible template, accent rule vs. sky** — rule "accent opposite the dominant wall hue" pushes the accent into the sky's hue family (205–235°) on a sunny day, so doors and sky can merge in the overview. Skill doesn't mention this tension. Fix: note it or require accent chroma ≥ 1.5× sky chroma.
14. **paperdolls-map-world §2/§3** — commands do `cd tools` then call `.venv/bin/python`, but the venv created at preflight is `<repo>/.venv`, so inside `tools/` the path is `../.venv/bin/python`. Fix: use `../.venv/bin/python` or run from repo root with `PYTHONPATH=tools`.
15. **paperdolls-map-world §2** — gives `--relation <id>` but no way to find the id for a named place (e.g. the commune of Jette) and forbids substituting a bbox for a named relation. Fix: add a lookup step (Nominatim / Overpass `rel["name"="Jette"]["boundary"="administrative"]`) and say who confirms the id.
16. **pipeline Gate 1 change vs map-world** — user wants n-buildings = residential buildings only. The map-world skill classifies economic classes but never says how to filter structures to "household/residential" or what happens to the non-residential ones (drawn as unbound scenery? dropped?). Rule 4 "nothing silently dropped" conflicts with a residential-only n-buildings. Fix: define "scenery structures" vs "bound structures".
17. **pipeline Failure playbook "Overpass unreachable" / map-world §2** — Overpass answered HTTP 502 ("at capacity") three times, plus on two mirrors; succeeded after ~3.5 min of backoff (30s/60s/120s). The playbook says "save query.ql … stop without data" and map-world says "stop", with no retry/backoff guidance for a transient 502/429. Fix: say "retry with backoff up to ~5 min, then stop"; also document `--endpoint` mirrors.
18. **paperdolls-map-world §5 vs. ingest output** — report says "frame rotated 0.0°, asset share 29% (unrotated 26%)" but a 0° rotation IS the unrotated case; the two numbers disagree and "North points 60° clockwise from the top of the screen" with rotation 0 is not explained. Skill's "read the report aloud" gives no way to reconcile them. Fix: explain or fix the report (29 vs 26; the 60° convention).
19. **paperdolls-map-world §2 (cascade) / ingest** — 93% of Jette buildings are bare `building=yes`; the seeded fallback gives them classes from "the local mix of tagged buildings": 228 'hospital', 242 'school', 176 'university', 70 'supermarket' for a commune with 18 tagged hospitals and 17 schools. The report only warns once; nothing stops hospitals being assigned to random houses and then rendered/bound as such. For a residential-model world this seeded noise matters (visual class, and which buildings count as households). Fix: for `building=yes` with no tag, prefer 'unknown-residential' / area-based rule over sampling non-residential classes.
20. **paperdolls-map-world §5 "residential" field** — the report distinguishes residential (433) / probable (7672) / other (1111), but no skill says which of these a model's households may stand on, or that the user must decide it. Needed here because the user asked for n-buildings = residential buildings. Fix: state in pipeline Gate 5/map-world that "probable" is a user decision, and show both counts.
25. **paperdolls-beauty-review §2 (squint: "mean within 100–130") vs. a sunny bible** — The squint band and the "light share ≥ exemplar" rule are calibrated on the Ashford exemplar (an after-rain 4 pm scene, mean 112). A clear sunny afternoon with ground L 0.95 renders at mean ~140 at the recipe's exposure 1.3; the review would fail a world for being sunny. Fix: make the band relative to the bible's moment (light-and-time §3 has exposure 0.95 for midday) or state that exposure must be lowered for bright moments (I used 1.12).
26. **paperdolls-scene-craft/recipes/buildings.md §1–2** — OSM terrace rows are often mapped as one long footprint (50–100 m). The recipe's masses/roofs have no rule for these (one gable roof over 60 m reads as a barn; flat reads as a slab). I split nothing and used a gable along the long axis for rows < 1,400 m². Fix: add a "row splitting" rule (cut long rects into 5–7 m plots with alternating wall/roof tones).
27. **buildings.md vs landmark** — no recipe for a church landmark (nave + tower + spire). Wrote one (gable nave 10.5 m, tower 6 m sq + 17 m spire on the min-area rectangle, since the real footprint is a cross at fill 0.78). Fix: add a landmark-church recipe or a general "landmark" part set.
28. **paperdolls-scene-craft SKILL §6 / camera.md** — snapshot contract and `__paperdollsReady` are specified but not who implements the capture script's expectations for `view=top` (up vector at elevation 90°). I had to special-case `camera.up` at el=90.
29. **paperdolls-scene-craft SKILL (intro: "There is no renderer in this repository")** — For a real city this means writing ~1,500 lines of three.js from scratch before Gate 4 can show anything (pipeline, ground, buildings, facades, trees, camera, snapshot contract, vite config, package.json). The recipes give snippets for the pipeline and shapes but nothing for assembly: how to load scene.json (9.5 MB inline JSON is too big; I wrote compose.py to emit a 2.5 MB compact file), tiling/lazy facades for 9k buildings, coordinate flip (scene y is south), camera/overview fit for an irregular outline. Fix: a "scale" section in performance.md (inline-data size budget, lazy tile build) and a coordinate-convention note in camera.md.
30. **paperdolls-beauty-review §2 Gate 4 subset** — Criterion 6 "street and ground" needs crossings, parked cars, lamps, hedges; but cars/pedestrians are scene-craft step 6 (life). A Gate-4 style frame without any vehicles or people cannot reach the exemplar's 4 on criterion 6 without doing part of step 6. Fix: move parked cars + lamps into step 3 (streets) or exclude criterion 6's vehicle part from the Gate 4 bar.
31. **paperdolls-beauty-review §1 — capture dir semantics** — `--round` directories are the only record; I deleted rounds 1–2 captures to keep the folder small and lost the ability to show the progression. The skill should say "keep every round's captures" (and the page build must not empty visual/ — it doesn't, but a human cleanup can).
32. **recipes/buildings.md §4 (facades) vs. OSM footprints** — OSM walls are split into many 0.5–2 m edges (buttresses, chamfers). The facade algorithm assumes one face per ≥3 m edge and drops the rest, leaving large blank walls (one large blank wall on the church-school complex is still unresolved in the style frame). I added collinear-run merging for non-rect footprints; it did not fix that wall. Fix: add "merge collinear edge runs" to §4 and say how to find blank faces (a debug mode that tints faces with no module).
33. **paperdolls-pipeline §Gate 5 / tools/check-schemas.py** — the pipeline expects a schema check for model-binding.json but `tools/check-schemas.py` does not exist in this checkout (preflight FAIL, #2). I validated with `jsonschema` directly. The schema has no place for `displayed_fields` or the units-per-building rule (accepted via additionalProperties, but the page code has no contract for them) nor for a *categorical* top colour on a 3-state field (top_color.domain/ramp assume a numeric sequential variable).
34. **tools/check-world.py** — the Gate 1–7 decisions-log check is satisfied by the template's own placeholder lines ("YYYY-MM-DD — Gate 6 …"), so it can pass with Gates 6–7 unrecorded; and "Snapshot: missing a date" fails until the very end. Fix: ignore lines with YYYY placeholders; make the snapshot check a Gate 7 check.
35. **Gate 1 brief** — I told the user "44 live controls"; the model has 40 (33 sliders + 4 switches + 3 choosers). The skill gives no extraction script, so counts were eyeballed; I corrected it at Gate 5 from the XML. Fix: ship a small `.nlogox` widget lister in tools/.
36. **paperdolls-netlogo-to-ts §3–§5 (and tools/agents/parity)** — the harness (`run-netlogo.mjs`, `run-ts.ts`, `procedures.mjs`, `determinism-*.mjs`) is hard-wired to Wolf Sheep: defaults for setup/constants/pens, no way to pass params to `run-ts.ts` (only `--seed-param`), `scripts/procedures.mjs` is a wolf-sheep fixture recorder. For this model I wrote `sim-code/parity/{run-ts.ts,procedures.ts,matrix.mjs,determinism.mjs,exact.mjs,map-run.ts}`. The skill should say a world brings its own gates and the shared harness is only a template.
37. **paperdolls-netlogo-to-ts §1 (reading)** — NO guidance on NetLogo parse rules that bite a converter: prefix reporters take arguments WITHOUT infix (`int (hash-uniform s k 2 * 4294967296)` is `int((hash-uniform s k 2) * 2^32)`, not a 3rd argument `2*2^32`). I read it the wrong way first; only the NetLogo comparison caught it (areas differed). Fix: add a "NetLogo precedence gotchas" list (prefix-vs-infix, `max (list ..) * x`, 0-based `item`, floored `mod`, `round` half-up, `cos` in degrees).
38. **paperdolls-netlogo-to-ts §5 (ensemble = KS on 200 runs)** — this model is fully deterministic given (seed, scene-seed) because all randomness is its own mulberry32 / hash_uniform; NetLogo and TS agree cell-for-cell at 1e-12 over 13 parameter configurations × 2 seeds × 360 ticks × 16 pens. An exact gate is far stronger than a KS ensemble, but the skill only offers the statistical gate. Fix: add "if the model never calls NetLogo's `random`, gate exactly; ensembles are for models that use NetLogo's RNG".
39. **netlogo-to-ts / pipeline Gate 6 vs map mode** — parity is only possible in "synthetic" mode (the NetLogo model owns a synthetic building table); the real-map mode (footprints from OSM) has no NetLogo twin. I made the model take the building table from `world.layers.buildings` only for the footprint/storeys draws, so that everything downstream is the same code, and ran parity in synthetic mode. The skill has no concept of a model with two building sources; the limit (parity ≠ map mode) must be stated in the final report.
40. **paperdolls-technology §3 (runtime)** — says a model with step < 2 ms and < 2,000 agents may run on the main thread; this model at 31,287 households takes 24 ms per step (46 ms worst), so a worker is mandatory, and the per-tick frame (31k household rows + 8k building rows as typed arrays) is a design decision the skill leaves open (transfer cost, which fields to send).
41. **paperdolls-interface-ui §7** — points at `reference/panels/` which does not exist (only `shell.tsx` and `theme.ts`). Every panel (controls, charts, impact graph, legend, drawer) was written from the §3 table.
42. **paperdolls-technology §3 / §6 vs. the Vite build** — says bundle `model.ts` into the worker with esbuild; I used Vite's inlined worker (`?worker&inline`), which bundles the model and the library with the same toolchain and keeps one file. The skill should say that is acceptable, and how the worker is expected to receive the world (I post compact building arrays and rebuild a `World` inside the worker).
43. **tools/bench/fps.mjs + technology §5 budgets** — `fps.mjs` measures only the page's default state, over vsync-capped rAF (p50 = 16.7 ms is just the display), so it cannot tell a 2 ms frame from a 16 ms one and cannot set a zoom level or start playback. I wrote `page/fps-all.mjs` (three zooms × idle/playing × dpr 1/2, plus uncapped render cost and draw calls). Against the perf recipe's budgets (≤ 250 draw calls, ≤ 1.5 M visible triangles at neighbourhood) this world is over (454 calls, 8.9 M triangles counted across shadow, normal and colour passes) while holding 60 fps on a real GPU (RTX 4080 SUPER). Fix: measure these in the tool and say how triangles are counted.
44. **recipes/data-in-the-world.md §2 (roof tint ≤ 10 %)** — a 8 % tint toward the pale end of a sequential ramp *raises* roof lightness well above the "≤ 0.03 L" rule (roofs went pink and merged with the walls). I restricted the tint to the mid/dark states. The recipe should say the tint must keep the roof's L (tint hue and chroma only).
45. **recipes/data-in-the-world.md §4 (flag)** — no rule for the *default* state of a mark. All ~4,000 condo buildings start "pending", so a pennant on each is visual noise; I show pennants for "approved" only in the beauty view and all pennants in the lens.
46. **paperdolls-scene-craft SKILL §6 (`t=`)** — "default: the tick where the top-colour field's IQR is largest" has no meaning for a categorical top colour; I used 0.75 × the horizon. Also `screenshots.mjs` waits 15 s for `__paperdollsReady`, and a snapshot that must run a 31k-household simulation to month 270 takes ~8 s; the script's silent fixed-wait fallback would hide a slower machine. Fix: a `?t=` budget note and a longer/explicit ready timeout.
47. **paperdolls-beauty-review rubric 4 and 6 for real places** — "skyline: height gradient, landmark in one second" is not reachable for an OSM town whose heights are 99 % assumed, and "street and ground" at 4 needs benches, hedges and plot surfaces which the pipeline treats as optional life. A real-place variant of the rubric (or an agreed ceiling) would stop worlds failing on data limits rather than craft.
48. **Gate 7 process (two-run comparison)** — "A two-run comparison matches the declared interventions" is checked, but nothing defines where the second run lives (worker, seed, whose map it colours). I ran the baseline in the same worker with the same seed and show it on the charts only.
